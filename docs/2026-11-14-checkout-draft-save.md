# 제작 코드 가독성과 입금 전 작성본 보관

- 제작 코드 입력을 별도 카드로 구분하고 전체 너비, 최소 높이 58px, 16px 글자, 대비 있는 테두리와 키보드 포커스를 적용했다. 제작 연결이 준비되지 않았을 때 기존 입력 제한을 유지하고 이유를 표시한다.
- 9,900원 가격 안내 아래에 ‘브라우저에 저장하기’를 추가했다. 질문 답변·요약·추가 작성 내용은 기존 질문 저장 경로와 잠금/충돌 검사를 통해 저장하며, 수동 저장 성공 시에만 완료를 표시한다. 작성 내용을 바꾸면 이전 완료 안내를 표시하지 않는다.
- 같은 기기·브라우저에서 이어 쓸 수 있음을 안내하고 구매/입금 안내 링크와 질문 작성본 JSON 보관 버튼을 제공한다. 브라우저 데이터 삭제와 공용 기기 이용 시 주의점을 설명한다.
- 동화 생성이나 AI 호출, 입금 확인 처리를 새로 실행하지 않는다. 제작 코드는 기존 sessionStorage 정책을 유지한다.

검증: `npm run typecheck`, `npm run test:engine`, `node scripts/question-store-test.cjs`, `npm run build`, `git diff --check` 통과.

이 환경에는 Sites 브라우저 검증 도구가 없어 실제 화면과 클릭 흐름은 검증하지 못했다. Netlify 배포는 실행하지 않았다. 기본 브랜치와 별도로 보관하며 커밋의 `[skip ci] [skip netlify]`로 자동 배포를 건너뛰도록 표시했다.

## 추가 위험 요소와 화면 이탈 보완

- Reader와 Checkout이 같은 제작 연결 상태를 사용한다. 확인 중/실패를 구분하고 ‘연결 다시 확인’을 제공한다. 재시도 전 요청을 중지하고 늦게 도착한 과거 응답을 무시한다.
- 새 대기 기록은 요청 UUID와 공개 주문 UUID를 함께 저장한다. 제작 코드 비밀값은 넣지 않는다. 다른 코드·다른 탭의 기록은 해제하지 않는다. 재시도 동의도 해당 주문에만 적용한다.
- 예전 UUID 단독 기록은 서버 요청/완성본 UUID가 같을 때만 자동 해제한다. 주문을 확인할 수 없는 예전 기록은 명시적인 확인 후 별도 브라우저 키에 먼저 보관하고 대기 목록에서 제외할 수 있다. 이 작업은 서버 취소나 불확실한 유료 재시도 동의가 아니다.
- 대기 기록 해제 전 서버를 조회한다. 제작 중이면 유지하고, 완성됐으면 책장으로 복원한다. 중단 상태와 서버 안내는 ‘동화가 없음’으로 바꾸지 않는다. 새 브라우저에서 중단/진행 중 주문을 조회해도 대기 기록을 복원한다.
- 생성 버튼 바로 아래에 미충족 조건을 설명하고, 최종 확인 후 가격·저장·코드 영역으로 이동하는 버튼과 저장본 복원 안내를 추가했다. 키보드 포커스와 동작 줄이기 설정을 고려했다. 질문 저장과 탭 임시 제작 코드 보관의 차이도 안내한다.
- 질문 작성 중 화면이 숨겨지거나 pagehide가 발생하면 기존 잠금과 충돌 검사를 통해 저장을 시작한다. 저장 대기·실패뿐 아니라 화면 내용과 저장본이 다른 경우에도 기존 이탈 경고를 적용한다.
- 탭 복귀/새로고침 후 유효한 코드와 대기 기록이 있으면 기존 결과만 조회한다. 그림도 화면 복귀 시 상태를 다시 읽는다. 불확실한 작업을 자동으로 재생성하지 않는다. 작업 중 코드 교체도 막는다.
- 서버가 접수한 온라인 글/그림 작업은 기존 Background Function에서 브라우저와 별도로 실행된다. 로컬 제작은 컴퓨터와 제작 서버가 켜져 있어야 한다. 접수 전 연결 종료나 서버 중단으로 완료되지 않은 작업은 기록을 보존해 상태 확인으로 안내한다.

검증: 타입 검사, `npm run test:checkout`(다른 주문/탭 기록 보호·예전 기록·보관 실패·중단 안내), 기존 질문 저장/파일 보관/복원 테스트, `npm run test:cloud`, 프로덕션 빌드 통과. 클라우드 모의 시험에 고객 연결 abort 후 고객 polling 없이 글·그림 18장 완성, 새 조회 복원, 중복 생성 없음 검증을 추가했다. 실제 OpenAI 호출과 고객 데이터는 사용하지 않았다.

브라우저 화면 도구가 없어 실제 모바일 앱 강제 종료와 BFCache 동작, Netlify 운영 환경은 검증하지 못했다. 브라우저가 강제 종료될 때 아직 저장하지 못한 마지막 입력까지 보장하는 것은 아니다. 자동 저장·저장 버튼·이탈 시 저장 시도·미저장 경고로 보호하며, 서버가 접수한 작업과 저장된 작성본의 복구를 구분한다. Netlify 배포 없이 같은 작업 브랜치에만 저장한다.
