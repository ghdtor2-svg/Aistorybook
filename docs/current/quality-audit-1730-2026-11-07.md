# 17:30 예약 재개 · 품질 점검 및 배포 인계

2026-11-07 한국시간 17:30에 예약 작업을 재개했다. 이 점검에서 추가 유료 API 생성은 하지 않았다. 이전 실제 API 실측 결과 4장을 재확인하고, 모의 생성 검사와 공개 배포용 검사로 수정 사항을 검증했다.

## 결론

- 실제 플랫폼 API에서 입체 인형·수채화 표지와 펼침면 각 1장씩, 총 4장이 성공했다. 예시와 비교할 만한 질감·인물 표현을 확인했다. 이는 두 화풍의 일부 결과이며, 나머지 8개와 작품 전체 18장까지 검증한 결과가 아니다.
- 화풍 참고 이미지와 실제 제작 결과를 구분하고, 실제 결과를 펼쳐 볼 수 있게 했다. 사계의 탑은 별도 편집한 기준 샘플이라고 표시한다.
- 최신 로컬·공개용 빌드, 질문 엔진, 32쪽·18장 구성과 본문 보존, 긴 요약 전달, PC·모바일 그림 비율·확대·닫기, 제작 코드·중복 생성 방지·결과 복구·수정 제한 검사를 통과했다.
- 공개 도메인을 모사한 검사에서 메인 샘플 두 장면, 10개 화풍과 확대 후 선택 유지, 실제 제작 예시 두 화풍, 모바일 넘침 방지, 전체 샘플 PDF를 확인했다.
- 공개용 빌드에는 직원 사무실·관리자 코드 발급·과거 그림 생성 경로가 없다. 온라인 제작과 결제는 아직 준비 중으로 안내하고 차단한다. 안전한 공개 주문 보관·장시간 처리 구조까지 완성됐다는 뜻이 아니다.
- 기존 책장의 예전 품질 형식·이야기 결(theme)·대화 질문(talkingPoints)을 보존하도록 고쳤고 확인했다.
- 멈춰 있던 로컬 서버를 다시 켰고, 실제 품질 예시와 호환 수정을 백업 후 반영했다. http://127.0.0.1:3000 에서 확인할 수 있다.

## GitHub와 사이트의 실제 상태

배포용 체크아웃은 작업 폴더 아래 `work/site-release`다. 기존 저장소는 `https://github.com/ghdtor2-svg/Aistorybook`, 기본 브랜치는 main, 점검 기준 원격 커밋은 `45cb519d7221a7fa2f04c7ff888f357da96e954e`다. 기존 Netlify 설정과 사무실의 로컬 전용 구분을 유지했다.

GitHub 연결 도구로 첫 소스 업로드를 시도했으나 **자동 승인 검토가 거절**했다. 이유는 공개 저장소 `ghdtor2-svg/Aistorybook`에 대한 사용자 명시 승인이 확인되지 않았다는 것이다. 따라서 업로드·푸시·사이트 반영은 완료되지 않았다. 우회 업로드를 하지 않았다.

승인받을 구체적 범위는 최신 플랫폼 코드, 화풍 WebP, 사계의 탑 공개 샘플 PDF·미리보기, 실제 API 품질 예시 4장, 현재 명세·가격안·검사 기록이다. 비밀 키·환경파일 실값·주문 데이터·고객 사연은 제외한다. GitHub 대상은 공개 저장소이므로 업로드된 소스와 샘플은 누구나 볼 수 있다.

공개 주소 `https://nangman-hanjul.netlify.app`는 아직 이전 안내문의 HTTP 503 상태다. Netlify 관리 화면에는 로그인이 필요하다. 이전 브라우저 조작은 현재 주소를 안전하게 판별하지 못해 중단됐다. 기존 문서에 크레딧 부족으로 배포가 멈췄던 기록이 있지만, 현재 계정의 크레딧 상태를 새로 확인한 것은 아니다.

## 승인 후 이어 할 일

1. 대표가 위 공개 저장소에 이 변경을 올리는 것을 명시적으로 승인했는지 확인한다. 승인 전에는 같은 전송을 다른 경로로 재시도하지 않는다.
2. GitHub main의 최신 커밋을 다시 읽고, 기준 커밋과 달라졌으면 새 변경을 보존해 통합한다. 강제 덮어쓰기를 하지 않는다.
3. 준비한 변경을 연결된 GitHub 도구로 저장한다. 터미널용 GitHub 로그인은 현재 없으므로 무한 로그인 재시도를 하지 않는다.
4. Netlify 배포와 공개 주소의 `release-info.json`에서 `2026-11-07-quality-proof-v1`이 실제 제공되는지 확인한다. GitHub 저장 성공만으로 배포 성공이라고 보고하지 않는다.
5. Netlify 계정 로그인·크레딧·배포 제한이 남으면 대표에게 필요한 조치를 알린다. 결제·업그레이드를 임의로 하지 않는다.
6. 전체 18장 품질·비용 검증과 공개 주문 저장·배경 작업은 별도 후속 작업이다.

## 예약과 사용량 한도

17:30 예약은 이 대화에서 실제로 실행됐다. 점검 후 일회성 예약을 정리하려고 삭제를 시도했으나, 자동 승인 검토가 ‘삭제에 대한 사용자 명시 승인이 확인되지 않는다’며 거절했다. 따라서 예약이 삭제됐다고 보고하면 안 된다. 설정은 COUNT=1인 일회성 예약이다. 삭제 정리는 사용자 승인 후 진행한다. 예약이 토큰 한도를 해제하거나, 한도 소진 때마다 자동으로 사용량을 복구하는 기능은 아니다.

17:41 확인: 검토용 패치가 준비된 Git 인덱스 변경과 일치하는 검사도 통과했다. GitHub 공개 업로드와 일회성 예약 삭제의 두 동작은 각각 자동 검토에서 거절되어 사용자 승인 대기 상태다. 이 대기 중 같은 동작을 다른 방식으로 우회하지 않는다.

후속 변경: 대표가 일회성 예약 삭제를 명시적으로 요청하여 `17-30` 삭제를 완료했다. GitHub 대상 승인 대기는 유지한다. 제작 안정성의 후속 수정과 검사는 `critical-fixes-2026-11-07.md`가 최신 기록이다.
