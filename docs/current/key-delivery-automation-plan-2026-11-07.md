# 수동 입금 확인 이후 제작 키 전달 자동화

## 권장 흐름

대표가 실제 입금을 확인하는 단계는 유지하고, 그 뒤 키 발급·안내 전송·처리 기록을 자동으로 연결한다. 초기 권장은 이메일 전달이며 고객 회원가입은 요구하지 않는다.

1. 고객이 주문할 때 입금자명 또는 대조할 별칭과 수신 이메일을 남긴다.
2. 대표가 실제 은행 입금 내역을 확인하고 주문의 ‘입금 확인’을 누른다.
3. 시스템은 해당 주문에 키가 이미 있는지 확인하고 한 번만 발급한다.
4. 준비된 이메일 발송함에 키와 이용 안내를 등록한다.
5. 전송 접수·전달 확인·실패 상태를 주문에 기록한다. 전송 접수만으로 고객 수신 완료를 단정하지 않는다.
6. 전송 실패 시에는 같은 주문의 같은 유효 키를 재전송한다. 메일 실패를 이유로 새 키나 추가 제작 권한을 만들지 않는다.

## 최초 이메일 안내 예시

제목: [낭만한줄] 동화 제작 키를 안내해 드립니다

입금 확인이 완료되었습니다.

제작 키: {{제작 키}}

동화 만들기: {{정상 운영 중인 서비스 주소}}

위 페이지에서 키를 입력하고 이야기를 작성해 주세요. 키는 다른 사람에게 공유하지 말아 주세요.

## 구현할 보호와 운영 기능

- 같은 주문을 반복 확인해도 중복 발급·중복 발송하지 않도록 주문과 발송 기록을 연결한다.
- 연락처와 발급 키는 운영 데이터로 보관하며 GitHub에 넣지 않는다.
- 이메일 오타 확인, 발송 실패 표시, 수신 주소 정정과 같은 키 재전송 기능을 둔다.
- 키를 중지하거나 재발급한 뒤에는 예전 키가 든 미발송 안내를 보내지 않는다.
- 발송 서비스 장애가 있어도 이미 확인한 입금과 발급 결과는 보존한다.
- 실제 서비스가 이용 가능한 상태인지 확인하고 발송 기능을 활성화한다. 현재 공개 사이트 제작 준비 상태와 연결 문제를 먼저 해소해야 한다.

## 채널 선택

이메일은 발송 계정·서비스 연결과 발신 주소 설정이 필요하다. 예를 들어 Resend의 Next.js 연결에는 API 키와 인증한 도메인이 필요하다. 특정 업체 가입이나 유료 상품 구매를 확정한 것은 아니다. [공식 연결 안내](https://resend.com/docs/send-with-nextjs)

카카오 알림톡은 비즈니스 채널 등 준비와 맞춤 안내 템플릿 검수 절차를 확인해야 한다. 초기에는 이메일부터 연결하고 주문량과 고객 선호를 확인한 뒤 도입하는 방안을 권장한다. [카카오 준비사항](https://docs.kakaoi.ai/kakao_i_connect_message/bizmessage/), [템플릿 심사 안내](https://kakaobusiness.gitbook.io/main/ad/infotalk/audit)

## 현재와 계획의 구분

현재 백오피스에는 관리자 입금 확인 후 발급·확인·복사·동일 주문 재발급·중지·관리 이력이 있다. 이메일 주소 수집, 실제 이메일·알림톡 발송, 발송함과 전달 결과 연동은 아직 구현되지 않았다. 고객에게 실제 메시지를 보내거나 새 발송 계정을 만들지 않았다.
