# 질문 선택지 적용과 선택 단계 부담 완화 (2026-11-10)

대표 지시는 세 가지였다. 첫째, 선택지로 답할 수 있는 질문은 보기에서 고를 수 있게 하고 보기 안에 ‘직접 입력’을 둔다. 둘째, 고르기 어렵고 직접 답하는 편이 나은 질문에는 보기를 넣지 않는다. 셋째, 앞서 추가한 선택 질문 9개가 선택으로 느껴지지 않을 수 있으니 부담을 줄이고, 보기 편하게 바꾼다. 이번 작업은 로컬 반영과 검증까지이며 공개 배포는 하지 않았다.

## 1. 어떤 질문에 보기를 두는가

판단 기준은 **보기가 사용자의 답을 대신할 수 있는가**다. 고를 수 있는 답이 정해져 있으면 보기를 두고, 실제 기억이나 구체적인 줄거리를 물으면 보기 없이 직접 쓰게 한다.

보기를 둔 핵심 항목 6개: 선물 대상, 주인공, 관계, 그때의 감정, 특별한 모습(좋아하는 것·성격 2묶음), 전하고 싶은 마음. 핵심 질문과 후속 질문 모두 담을 항목(`target`) 기준으로 같은 보기를 쓴다.

보기를 둔 선택 질문 6개: 읽는 아이와 목소리(나이·읽는 방법·분위기), 캐릭터(구성·고유색·지니는 물건), 세계와 약속(배경·상상 범위·계절), 마음이 바뀌는 과정(처음·마지막 마음), 그림으로 보고 싶은 장면(순간·느낌), 지킬 것과 피할 것.

보기를 두지 않고 직접 쓰게 한 질문 4개:

- 핵심 ‘가장 기억에 남는 순간’ — 실제 기억이다. 보기를 고르면 사건의 갈래만 남고 그날의 이야기가 빠진다.
- 선택 ‘목표와 가로막는 일’, ‘주인공이 직접 내리는 선택’, ‘처음의 단서와 마지막 장면’ — 그 동화에만 맞는 구체적인 줄거리다. 일반적인 문장을 고르게 하면 고르기도 어렵고 남의 줄거리를 받는 셈이 된다.

이 질문들은 펼치면 보조 설명과 쓰는 칸이 바로 나온다. 보기가 있는 질문은 보기를 먼저 보여 주고 쓰는 칸은 ‘보기에 없으면 직접 적어도 돼요’ 접기 안에 둔다.

## 2. 보기 동작

- 공용 선택지 로직은 `src/lib/storybook/story-choices.ts`, 화면은 `src/app/storybook/ChoiceChips.tsx`다.
- 보기를 누르면 답변 문장에 그 문구가 들어가고, 다시 누르면 지워진다. 여러 개 고를 수 있다. 화면 선택 상태를 따로 저장하지 않고 답변 원문 하나만 저장하므로 기존 저장 형식과 내보내기·가져오기를 그대로 쓴다.
- 묶음마다 ‘✏️ 직접 입력’ 보기가 있다. 누르면 입력칸이 열리고 적은 내용이 답변에 더해진다.
- 구분자는 쉼표와 줄바꿈만 쓴다. ‘이모·고모’처럼 가운뎃점이 들어간 보기를 쪼개지 않기 위해서다. 선택 판정은 구분자나 문장 끝으로 둘러싸인 조각만 같은 보기로 보므로 ‘분홍’이 ‘분홍 리본’ 안에서, ‘우리 집’이 ‘할머니 집’ 안에서 선택으로 잡히지 않는다.
- 고르지 않은 보기는 답변에 넣지 않는다. 선택지는 추천 문구일 뿐이며 사용자가 고른 내용만 생성 입력으로 전달한다.
- 보기 버튼에는 선택 여부를 `aria-pressed`로 알리고 문구를 `aria-label`로 고정했다. 답변 입력칸의 이름은 기존과 같은 ‘답변’으로 두어 기존 화면 검사와 접근성 이름을 바꾸지 않았다.

## 3. 선택 질문 9개 보는 방법

한 번에 한 질문씩 넘기던 방식(번호 동그라미 + 이전/다음 + 전체 접기)을 버리고 **9개 제목이 한눈에 보이는 접힘 목록**으로 바꿨다.

- 제목 9줄이 모두 보이고 내용은 전부 닫힌 채로 시작한다. 무엇을 묻는지 먼저 훑어보고 마음이 가는 것만 눌러 펼친다. 여러 개를 동시에 펼쳐 둘 수 있다.
- 줄마다 오른쪽에 ‘보기에서 고르기’ 또는 ‘직접 적기’를 적어 어떤 방식인지 미리 알 수 있게 했다. 고른 내용이 있으면 그 자리에 고른 내용을 줄여서 보여 준다.
- 네이티브 `<details>`를 써서 키보드와 보조기기에서 그대로 열고 닫힌다. ‘다음/이전’ 이동과 번호 표시를 없애 9단계를 통과해야 하는 느낌을 줄였다.
- ‘작성한 설계 항목 0/9’처럼 미완성으로 읽히는 표시를 없앴다. 대신 “지금 1가지 들려줬어요 · 더 안 해도 괜찮아요”, 아무것도 없으면 “아직 아무것도 안 골랐어요 · 그대로 넘어가도 괜찮아요”로 적는다.
- 머리말에 “여기부터는 선택이에요 · 안 해도 괜찮아요”와 “하나도 고르지 않아도 동화는 그대로 만들어지고, 바로 ‘내용 최종 확인’을 눌러도 괜찮아요”를 두었다. 실제로 하나도 열지 않아도 최종 확인을 누를 수 있다.
- 선택지 묶음마다 “여러 개 골라도 되고, 안 골라도 돼요”를 적었다.

## 보존한 것

기존 질문 ID와 저장 버전, 선택 질문 9개의 ID·순서·분기, 저장 형식, 작성본 JSON/TXT 내보내기·가져오기, 책장과 고객 주문을 바꾸지 않았다. 생성 입력 전달 방식(`storyBrief`)도 그대로다.

- `npm run test:engine` 통과(핵심 질문 흐름·저장·수정 회귀).
- `node scripts/story-design-test.cjs`, `question-draft-test.cjs`, `question-import-test.cjs`, `question-store-test.cjs` 통과.
- `node scripts/story-choices-test.cjs` 통과: 선택·해제, 전체 선택 후 전체 해제, 다른 보기 안의 글자를 같은 선택으로 보지 않음, 직접 쓴 문장 보존, 직접 입력 추가와 중복·길이 제한, 보기를 둔 항목과 두지 않은 항목이 의도한 목록과 정확히 일치함, 보기가 있는 질문은 누르기만 하고 없는 질문은 직접 써서 핵심 질문 5개를 끝까지 저장.
- `tests/question-choices.spec.ts` 3건 통과(390×844): 보기 선택·해제와 직접 입력·새로고침 유지, 기억 질문에 보기가 없고 직접 써서 저장됨, 선택 질문 9줄이 모두 닫힌 채 보이고 열지 않아도 최종 확인 가능·펼쳐 고른 내용이 제목 줄과 저장본에 남음·가로 넘침 없음.
- 기존 질문 화면 브라우저 검사 통과: storybook, question-import, question-concurrency, question-file-cancel, question-rescue(1건).
- 기존 실패 6건은 이번 변경과 무관하다. leave-guard 3건과 question-rescue 2건은 `aae21d9`에서 공개 동화 화면의 ‘직원 사무실’ 링크를 뺀 뒤 검사만 그대로 남은 것이고, story-recovery 1건은 변경을 모두 치운 HEAD 상태에서도 똑같이 실패하는 것을 확인했다. 이번 작업에서 고치지 않았다.
- `npm run typecheck:browser`는 Windows에서 `tests/*.spec.ts` 글롭이 확장되지 않아 실행되지 않는다. 글롭을 펼쳐 직접 실행해 이번에 추가한 검사에 형 오류가 없음을 확인했다. 다른 기존 검사 파일의 암시적 any 오류는 그대로 남아 있다.

## 범위 밖

공개 사이트 배포는 하지 않았다. 선택지를 넣었다는 것이 실제 글·그림 품질 향상을 뜻하지는 않으며, 생성 결과 비교 실험은 이번 작업에 포함하지 않았다.

별도로 확인한 것: 동화 질문 화면은 화풍 예시와 샘플 이미지 약 7MB를 한 번에 내려받아 개발 서버에서 첫 화면이 몇 초간 버벅인다(측정 2fps). 이번 변경과 무관한 기존 상태이며 고치지 않았다. 공개 사이트에서 체감이 어떤지는 따로 확인이 필요하다.
