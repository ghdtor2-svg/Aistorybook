# 백오피스와 고객 사이트 연결 — 2026-11-07

## 구현한 연결

관리 화면은 대표 PC의 `/office/orders`에서만 사용합니다. 공개 빌드에는 사무실 화면과 로컬 관리자 API를 포함하지 않습니다. 온라인 공유를 켜면 로컬 백오피스는 서명된 관리 요청만 기존 Netlify 사이트로 전달하고, 고객 사이트와 같은 비공개 Netlify Blobs 저장소의 주문·키·작품을 사용합니다. 로컬 관리자 비밀번호는 전송하지 않습니다. 공유 연결 실패 시 로컬 주문으로 대신 발급하지 않습니다. 저장 위치를 관리 화면에 표시합니다.

입금 확인과 키 전달은 대표가 합니다. 현재 5,000원이며 로그인 없이 제작 코드를 사용합니다. 이메일 수집·자동 발송은 이번 작업에 포함하지 않았습니다. 기존 로컬 주문과 고객 데이터는 업로드하거나 옮기지 않았습니다. 연결 이후 발급하는 새 온라인 주문이 대상이며, 기존 로컬 키를 그대로 온라인에서 사용할 수 있다고 안내하면 안 됩니다.

온라인 글과 그림은 Netlify Background Functions에서 처리합니다. 한 번에 글 1편 또는 그림 1장을 실행하고 다음 그림을 이어 요청합니다. 정상 배포·설정 후에는 대표 PC와 고객의 브라우저가 꺼져 있어도 온라인 작업이 가능합니다. 이것은 구현 구조에 대한 설명이며 실제 운영에서 검증 완료한 상태는 아닙니다.

## 중복 비용과 접근 제한

- 공유 주문은 강한 일관성으로 읽고, 버전이 일치할 때만 저장합니다. 동시에 같은 작업을 요청해도 한 요청만 제작을 시작합니다.
- 관리 요청과 작업 요청은 서로 다른 비밀값으로 서명합니다. 본문 위변조, 60초 이상 지난 요청, 같은 요청의 재전송을 거절합니다.
- API 결과가 불확실한 작업은 멈추고 사용자의 재시작 확인을 받습니다. 플랫폼의 자동 재전송만으로 유료 호출을 반복하지 않습니다.
- 그림은 공개 폴더가 아닌 비공개 저장소에 두고 유효한 키로 해당 주문의 그림만 엽니다. 키 재발급과 중지를 고객 API에서 즉시 확인합니다.
- production 설정, 정식 사이트 주소, 공유 저장소와 AI 연결 설정을 확인한 경우에만 고객의 제작 코드 입력을 엽니다. 미설정·배포 미리보기에서는 닫힙니다.

## 확인한 결과

1. `npm run test:cloud` 통과. Netlify 저장소의 조건부 쓰기 계약을 메모리 모형으로 검사했습니다. 서명·재전송·만료, 동시 변경, 같은 주문의 동일 키, 글 1회, 그림 18장, 비공개 그림, 실패 후 확인 재시도, 키 교체·중지, 미리보기 차단, 원격 오류에서 로컬 대체 없음. 모든 AI 호출은 가짜 응답이며 비용이 발생하지 않았습니다.
2. 기존 로컬 회귀 검사 통과. 탭을 닫은 뒤 그림 18장 완주, 32쪽, 원래 비율, 그림 수정, 백오피스 입금·발급·검색·메모·재발급·중지·로그아웃, PC·모바일을 검사했습니다.
3. 핵심 질문 엔진 검사 통과. 실제 고화질 API 품질 검증은 이전의 입체 인형·수채화 4장 결과와 동일합니다. 이번 연결 시험을 새 실제 API 품질 실측으로 표시하지 않습니다.

## 실제 연결 전 남은 설정

Netlify 기존 계정 로그인 후 계정 화면에서 다음 안내를 확인했습니다: 팀에 운영 크레딧만 남았고 production deploys가 중단되어 있습니다. 계정 요금제 변경이나 결제는 하지 않았습니다. GitHub 저장과 실제 배포 성공은 별개입니다. 현재 이 제한 때문에 새 온라인 연결의 실배포와 실제 Blobs 저장·Background Functions 실행을 검증하지 못했습니다.

배포 가능 상태가 되면 다음 순서로 마무리합니다.

1. 실제 로컬 앱 폴더에서 `node scripts/cloud-connection.cjs prepare`를 실행합니다. 기존 로컬 API 설정을 읽어 `.office-data/cloud-connection/netlify.env`에 새 연결용 비밀값과 Netlify 설정을 만듭니다. 파일은 PC에만 보관하고 채팅이나 GitHub에 보내지 않습니다.
2. 해당 설정을 **기존 nangman-hanjul 사이트의 production Functions 환경**에만 넣습니다. API 키와 두 연결 비밀값이 들어가므로 대표가 직접 입력·가져오기하거나 해당 사이트에 저장할 별도 승인을 받은 뒤 처리합니다. `NEXT_PUBLIC_OFFICE_LOCAL`, 로컬 관리자 비밀번호, `NANGMAN_REMOTE_URL`은 Netlify에 넣지 않습니다. deploy-preview에는 production 저장소 인증을 주지 않습니다.
3. GitHub main 최신 코드로 정상 배포하고 availability의 ready=true, 공유 저장소 접근, 서명된 관리 연결을 확인합니다. 유료 제작 전에 가상 주문으로 키 발급과 중지·복구를 확인합니다.
4. 로컬에서 `node scripts/cloud-connection.cjs activate`를 실행합니다. 서명된 원격 목록과 고객 준비 상태 확인에 모두 성공한 경우에만 로컬 관리 연결을 바꾸고 기존 로컬 설정을 백업합니다. 503이나 인증 실패 시 로컬 설정은 유지합니다. 로컬 서버 재시작 뒤 화면의 ‘고객 사이트와 공유 중’을 확인합니다.
5. 대표 PC를 끈 상태의 실제 온라인 작업, 모바일 복구, 키 중지 후 접근 차단을 검증한 뒤 서비스 연결 완료로 보고합니다. 실제 AI 시험은 사전에 범위와 비용을 정하고 진행합니다.

현재의 로컬 발급·기존 주문을 유지하기 위해 원격 연결은 아직 켜지 않았습니다. 기존 주문 이전, 보관 기간·고객 삭제 요청, 자동 키 이메일 전달은 별도 후속 과제입니다. 오래된 단계별 문서와 충돌하면 이 연결 상태 기록을 우선합니다.
