# 낭만한줄 서비스 명세서 · 외부 AI 검토용

기준일: 2026년 11월 7일. 실제 소스와 기존 검증 기록을 기준으로 작성했다. 이 문서는 완성된 상용 서비스의 기능 보증서가 아니다. **현재 구현, 제작 목표, 미구현 제안을 구분**한다.

후속 개선 반영: 신규 펼침면은 그림 위·아래 배치를 번갈아 사용한다. 그림 확대와 수정 대상 미리보기를 추가했다. 생성 요청은 확인된 요약을 전체 전달하며, 총 100,000자를 넘으면 잘라 보내지 않고 오류를 안내한다. 모의 API로 긴 입력 전달과 PC·모바일 확대·닫기 및 기존 제작 흐름을 확인했다.

## 1. 서비스와 사업 목표

- 서비스명: 낭만한줄
- 상품명: AI 맞춤형 동화 생성 서비스
- 고객: 아이의 정보와 가족의 경험을 특별한 이야기로 남기고 싶은 부모·보호자. 구체적인 핵심 연령대와 구매 동기는 시장 검증 대상이다.
- 제공 가치: 질문에 답하는 방식으로 이야기 소재를 정리하고, 개인화된 글과 선택한 화풍의 삽화를 제작한다.
- 사업 단계: 매출 극대화보다 상품의 시장성, 가격 수용도, 결과물 만족도를 확인하는 단계.
- 현재 확정 판매가격: 동화 1편 5,000원. 계좌이체를 운영자가 확인한 뒤 제작 코드를 발급하는 방식.
- 실물 동화책 제작·판매는 현재 사업 범위에서 제외한다. 최종 디지털 제공 형식은 확정 전까지 고객에게 약속하지 않는다.
- 인스타그램 등 외부 게시물은 대표의 최종 승인 후 게시한다. 공개 구매 가능 여부를 확인하기 전에는 구매를 유도하지 않는다.

## 2. 현재 준비 수준 — 먼저 확인할 사항

**현재는 로컬 제작·검토 단계다. 일반 고객이 인터넷에서 바로 구매하고 끝까지 이용할 수 있는 공개 서비스가 완성된 상태는 아니다.**

생성·삽화 기능은 로컬 주소에서만 요청을 받도록 제한되어 있고 Netlify 환경의 요청을 차단한다. 따라서 Netlify의 이용 제한이 풀리는 것만으로 공개 서비스가 작동하지 않는다. 공개 운영을 위한 서버, 저장소, 접근 보호와 작업 처리를 별도로 준비해야 한다.

초기 명세 검토 후 실제 플랫폼 API로 입체 인형·수채화의 표지와 펼침면을 각각 1장씩, 총 4장 생성했다. 모두 성공했고 시각적으로 고품질 표현과 다음 장면의 인물 유지가 확인되었다. 18장 전체 또는 다른 8개 화풍까지 검증한 것은 아니다. 자세한 기록은 별도 실제 API 품질 보고서를 따른다.

## 3. 기본 상품 구성과 품질 목표

| 항목 | 기준 | 현재 상태와 한계 |

| 글 | 약 5,000자 | 생성 결과 본문 4,500~6,500자 검사. 생성 지시는 4,500~6,000자 |

| 펼침면 | 양쪽 페이지에 하나의 그림이 이어짐 | 본문 14쌍은 공유 그림, 1쌍은 개별 그림 2장, 마지막 단독 페이지 그림 1장 |

본문 4,500~6,500자를 31쪽으로 나누면 단순 평균은 쪽당 약 145~210자다. 실제 페이지마다 글자 수는 다르다. 글꼴 크기와 화면 폭에 따라 웹에서 보이는 높이도 달라진다.

**샘플과 자동 생성의 차이:** 「사계의 탑」은 별도 제작과 수동 편집·확인을 거친 PDF다. 플랫폼은 그 구성을 자동화하는 단계이며, 현재 공유 펼침면은 그림을 글 위·아래에 번갈아 배치한다. 샘플 수준의 다양한 글·그림 배치가 모두 자동 구현된 것은 아니다. 과거 화면의 여러 배치 방식도 신규 32쪽 화면 전체에 적용된 상태는 아니다.

## 4. 고객 이용 흐름

1. 회원가입 없이 이야기 소재 질문에 답한다.
2. 5개 핵심 질문 묶음과 묶음별 최대 2개의 추가 질문으로 소재를 정리한다. 최대 15개 질문이다.
3. 요약을 확인하고 수정한다. 허용할 창작·각색 내용을 확인해 최종 확정한다.
4. 화풍 예시를 보고 원하는 화풍을 선택한다.
5. 운영자에게 받은 제작 코드를 입력한다. 요약·각색 정보를 AI에 보내는 데 동의하고 글 생성을 시작한다.
6. 생성된 글을 읽고 직접 고칠 수 있다. 삽화는 별도로 제작을 시작하면 순서대로 생성된다.
7. 웹 책장에서 읽고, 글자 크기를 바꾸고, 백업할 수 있다.
8. 전체 삽화 제작이 완료된 뒤 그림 한 장을 골라 수정 요청을 1회 할 수 있다. 원본과 수정본을 선택할 수 있다.

계좌이체 안내와 코드 전달은 운영자의 수동 업무가 포함된다. 코드 발급이 은행 입금 내역과 자동 연동되는 것은 아니다.

## 6. 화풍

수채화, 과슈 동화, 서정 애니메이션, 히어로 코믹스, 입체 인형, 색연필, 파스텔, 수묵 담채, 유화, 양모 펠트.

선택한 화풍을 작품 정보에 저장해 다시 열기와 그림 제작·수정에 유지한다. 이후 다른 작품의 선택을 바꿔도 기존 작품의 화풍은 바뀌지 않는다. 최신 열 가지 예시는 각 기법을 드러내는 서로 다른 소재로 교체했고 특징 설명과 확대 보기를 제공한다. 고객 작품의 인물은 이야기 소재에 맞게 생성하며 예시의 인물을 그대로 복사하지 않도록 지시한다. 메인에는 별도 편집한 「사계의 탑」 표지와 두 펼침면을 미리 볼 수 있다.

## 7. 생성과 편집의 실제 구조

- 글 모델: 기본 `gpt-4.1-mini`. 환경 설정으로 변경 가능.
- 그림 모델: `gpt-image-2`, 고품질 설정.
- 그림 크기: 표지 1024×1536, 공유 펼침면 3072×1024, 일반 본문 그림 1536×1024.
- 첫 그림은 선택한 화풍 예시를 참고하고 이후 그림은 표지를 참고한다. 그림 속 글자는 생성하지 않도록 지시한다.
- 페이지 나누기는 문장과 글 길이를 이용한다. 별도 그림이 들어갈 전환 펼침면은 내부 이야기 경계를 참고해 선택한다. 이야기 의미를 전문 편집자처럼 분석하는 기능은 아니다.
- 그림 요청은 저장된 로컬 작업과 별도 작업자가 한 장씩 처리한다. 탭을 닫아도 컴퓨터와 로컬 제작 서버가 켜져 있으면 이어 진행하고 재접속 시 상태를 가져온다. 완료 여부가 불확실한 요청은 자동 재시도하지 않는다. 공개 클라우드의 지속 작업·영속 저장까지 구현된 것은 아니다.
- 입력 요약과 허용 각색은 확인된 내용을 전체 전달한다. 총 100,000자를 넘으면 생성 전에 길이 초과를 안내하며, 내용을 자동으로 자르지 않는다. 이는 입력 보존 기능이며 AI가 모든 소재를 작품에 반영한다고 보장하는 것은 아니다.
- 글 수정 후 자동 페이지 재분배로 그림과 문장의 대응이 달라질 수 있다. 수정 영향 범위를 확인하는 절차가 필요하다.

## 8. 저장·보호·운영

질문과 책장의 편집 내용은 브라우저 저장소에 보관한다. 주문, 생성 원본과 그림은 현재 서버의 로컬 파일에 저장한다. 브라우저에서 삭제한 내용과 서버의 생성 기록 삭제는 같은 작업이 아니다.

제작 코드는 생성·복구·그림 접근에 사용하는 비밀 정보다. 계정이 없으므로 코드 유출·분실 대응과 기기 변경 시 안내가 필요하다. 개인정보 보관 기간, 서버 데이터 삭제, 백업·복구 정책도 공개 운영 전 확정해야 한다. 글 API 요청의 저장 옵션을 꺼 두었다는 사실만으로 외부 AI 사업자의 데이터 보관이 전혀 없다고 홍보하면 안 된다.

공개 운영 전에는 주문·그림의 영속 저장소, 접근 권한, 요청 횟수 제한, 중복 실행 제어, 운영자 화면 보호, 비용 상한과 오류 기록을 점검해야 한다. 현재 단일 로컬 서버용 잠금과 파일 보관만으로 다중 서버 운영까지 보장하지 않는다.

| 전면 재제작 | 9,900원 | 제안, 미구현 |

기존 원가 검토의 API 예산은 **한 편 약 3,900~4,500원**이다. 18장, 참조 입력, 글 생성 및 제한적인 수정 여유를 가정한 추정치이며 실측 청구액이 아니다. 달러당 1,500원의 가정 환율을 사용했고 서버·보관·수수료·세금·고객 응대는 제외했다. 공식 가격표와 계산기 표시 차이 때문에 보수적으로 산정했으며 실제 계정의 청구량으로 다시 확인해야 한다.

출처와 계산 가정은 별도 「32쪽 기본 상품과 가격 제안」 문서에 정리되어 있다. 최신 원가 산정에는 [공식 API 가격표](https://developers.openai.com/api/docs/pricing)와 [이미지 생성 문서](https://developers.openai.com/api/docs/guides/image-generation)를 다시 확인해야 한다.

현재 가정대로라면 5,000원 판매 시 API 예산을 제외한 금액은 약 500~1,100원이다. 이것은 순이익이 아니다. 실패·재시도와 고객 응대까지 고려한 가격 검증이 필요하다. ChatGPT 개인 구독료와 고객에게 판매하는 동화 가격도 별개다.

## 10. 검증된 범위와 아직 확인하지 못한 범위

기존 검증 기록에서 빌드, 질문 진행, 페이지 분배와 본문 보존, 코드 발급·복구, 중복 생성 방지, 삽화 이어 만들기·수정 제한, PC·모바일 표시를 확인했다. 현재 32쪽·18장 전체 흐름의 검증에는 가짜 API 응답을 사용했다.

**가짜 응답 검증은 실제 그림 품질·제작 시간·청구액을 증명하지 않는다.** 최신 실제 API 점검에서는 입체 인형·수채화의 표지·펼침면 총 4건이 성공했다. 두 화풍의 표현과 표지 참조에 따른 인물 유지가 확인되었고 요청당 약 47~88초였다. 이 일부 실제 결과와 수동 완성한 샘플 PDF도 신규 표준 작품 1편의 자동 제작 성공을 대신하지 않는다. 실측 청구액은 아직 확인하지 않았다.

남은 핵심 검증은 실제 API로 신규 표준 작품 전체를 제작해 글 품질, 18장 캐릭터 일관성, 잘림, 장면 대응, 완료 시간, 실패 복구와 청구액을 함께 확인하는 것이다. 반복 검증은 유료 사용 범위와 예산을 정한 뒤 진행한다.

## 11. 품질 개선 우선순위와 완료 기준

| 순서 | 개선 과제 | 고객에게 생기는 변화 | 완료 여부를 판단할 기준 |
| --- | --- | --- | --- |
| 1 | 실제 한 편의 완주 검증·비용 기록 | 샘플 수준을 실제로 제공할 수 있는지 확인 | 글과 그림 18장 완료, 장면·인물 검수, 시간·사용량·청구액 기록 |
| 2 | 장시간 제작 안정화와 공개 운영 기반 | 화면을 닫거나 중간 오류가 나도 결과를 받음 | 서버가 작업 지속, 다시 접속해 상태 확인, 중복 과금·그림 중복 제작 방지, 공개 환경 검증 |
| 3 | 그림과 글을 함께 설계하는 편집 | 반복되는 상하 배치를 벗어나 동화책처럼 읽힘 | 장면별 배치 선택, 글·얼굴 겹침 방지, 중앙 접힘 안전 영역 검수, 그림 전체 보존 |
| 4 | 캐릭터·내용 일관성 강화 | 장면마다 얼굴·의상·고유색과 사건이 유지됨 | 인물 설정표·참조 체계, 이야기와 그림 대응 점검, 오류만 골라 재작업 |
| 5 | 모바일 읽기와 페이지별 수정 | 큰 그림과 글을 편하게 보고 원하는 곳만 고침 | 확대 보기, 읽는 순서 유지, 페이지/공유 그림의 수정 범위 표시, 원본·수정본 비교 |
| 6 | 입력 보존과 맞춤 이야기 품질 | 가족 사연이 빠지지 않고 아이에게 맞는 글이 나옴 | 중요한 입력 잘림 방지, 연령·어휘·읽기 난이도 확인, 핵심 사연 반영 점검 |
| 7 | 고객 작품 PDF 제작 연결 | 본인의 결과물을 안정적인 파일로 받음 | 실제 생성 그림 포함, 글 넘침·누락·잘림 없음, 32쪽 검증과 재다운로드. 제공 조건 확정 후 노출 |
| 8 | 상품 정책·데이터 관리 확정 | 비용·수정·실패 처리와 보관 조건을 미리 이해 | 가격 확정, 수정 전 금액 안내, 실패·환불·재시도 기준, 보관·삭제·코드 분실 대응 |

먼저 제작을 끝낼 수 있는지와 원가를 확인하고, 이어 읽기·편집 품질을 개선하는 순서가 적절하다. 회원가입 추가는 필수 선행 과제가 아니다. 초기에는 코드 방식으로 검증하면서 기기 변경·분실 문제가 실제로 얼마나 생기는지 확인할 수 있다.

## 12. 시장 검증 시 기록할 항목

질문 작성 시작/완료, 요약 확인, 화풍 선택, 코드 입력 성공, 글 생성 성공, 그림 전체 완성, 완료까지 걸린 시간, 수정 요청 사유, 오류·재시도 횟수, 한 편당 실사용 비용, 결과물 만족도, 가격별 구매 의향을 기록한다.

공개 서비스와 결제가 준비되면 실제 구매 전환도 기록한다. 아직 관측하지 않은 지표를 성과로 보고하지 않는다. 초기 핵심 지표는 ‘완성해서 만족스럽게 읽은 작품 비율’과 ‘그 한 편에 든 전체 비용’이다.
