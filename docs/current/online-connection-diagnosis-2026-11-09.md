# 온라인 연결 진단 — 2026-11-09

GitHub main을 기존 Netlify production에 배포했다. 운영 공개 사이트와 동화 페이지의 200 응답을 확인했다. 운영 준비 상태가 처음에는 false였으며 다음 문제를 순서대로 확인했다.

- 사용자 설정에서 저장소 변수 이름의 대소문자와 연결 비밀값 길이를 수정했다. 실제 키나 보안값은 저장소에 기록하지 않았다.
- 운영 진단 코드가 `netlify_runtime`을 반환했다. Netlify 빌드의 비밀이 아닌 `NETLIFY`, `CONTEXT` 표시를 Next.js 서버 코드에 보존하도록 수정했다. 배포 미리보기와 로컬에서는 production 조건을 충족하지 않는다.
- 다음 진단 코드는 `request_origin`이었다. Netlify Next.js 어댑터가 내부 주소로 재구성한 request.url 대신 실제 Host를 정식 사이트 호스트와 정확히 비교한다. 임의의 forwarded-host는 사용하지 않고 브라우저 Origin 검사와 서명 인증은 유지한다.
- 변경 후 미서명 관리 요청은 준비 중 503 대신 인증 거절 403을 반환했다. 운영 구성 및 호스트 검사 통과를 확인한 것이며, 관리 인증 성공이나 주문 생성 성공을 뜻하지 않는다.
- 저장소 준비 검사는 지연 후 502였고 사용자가 제공한 함수 기록은 두 요청 모두 30,000ms였다. 저장소 클라이언트의 요청에 `cache: no-store`를 명시하고, 준비 상태 검사만 7초 제한과 고정 진단 코드를 추가했다. 주문·고객 정보·요청 URL·인증값·원본 SDK 오류는 로그에 남기지 않는다.

`npm run test:cloud` (모의 API), `npm run typecheck`, `NETLIFY=true CONTEXT=production npm run build`를 통과했다. 공개 빌드에 로컬 사무실과 로컬 관리자 API는 포함되지 않았다.

최신 저장소 진단 변경은 운영에서 별도 확인해야 한다. 실제 AI 생성, 저장소 쓰기, 관리 연결, 기존 PC 연결, 고객 주문 복구와 유료 API 품질 시험은 이 검사로 완료됐다고 보고하지 않는다. API 키의 존재 검사는 키 유효성·잔액·API 권한 검사가 아니다.
