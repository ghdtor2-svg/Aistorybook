# 고객 질문 안내와 이탈·복구 검증

## 질문이 동화에 쓰이는 방식

질문 제목 아래 ‘동화에는 이렇게 담겨요’ 안내를 추가했다. 핵심 질문과 후속 질문 모두 질문 그룹이 아닌 실제 답변 대상 필드로 안내한다. 이전 답변 수정 화면에서도 안내를 유지한다.

| 항목 | 안내 내용 |
| --- | --- |
| 선물 대상 | 동화를 선물 받을 사람이며, 이야기 속 주인공과 다를 수 있다. |
| 주인공 | 여기에 적은 이름이나 인물이 동화의 주인공이 되어 이야기를 이끈다. |
| 관계 | 선물하는 사람과 받는 사람의 관계를 바탕으로 말투와 애정 표현을 정한다. |
| 기억에 남는 순간 | 중심 사건과 배경 장면의 바탕이 된다. |
| 감정 | 주인공의 표정·대사·행동을 표현하는 데 쓴다. |
| 특별한 모습 | 인물의 특징과 장면의 소재가 된다. |
| 전하고 싶은 마음 | 결말과 마지막 메시지의 바탕이 된다. |

요약의 7개 항목과 허용할 각색, 선택 질문 9가지에도 사용 목적을 설명한다. 선물 대상·주인공·관계의 답변 힌트를 각각 구분했다. 질문이 바뀌거나 이전 답변 수정에 들어가면 제목으로 포커스를 옮겨 설명부터 볼 수 있게 했다. 안내와 입력칸은 aria-describedby로 연결했다.

제작 요청에도 선물 대상과 주인공을 구분하고, 확인한 주인공 이름·별칭·인물 구성을 임의로 바꾸지 않도록 명시했다. 실제 유료 AI 생성으로 이름 반영 품질을 시험한 것은 아니다. 질문 ID와 기존 답변 형식은 바꾸지 않았다.

## 브라우저 검증

설치된 Chromium과 프로덕션 빌드(next start)를 사용했다. 기존 관리형 미리보기는 Next.js에 맞지 않는 --host 옵션으로 시작에 실패했으므로, 프로젝트 테스트용 서버로 검증했다. 실제 고객 주문·개인정보·AI 호출 없이 합성 데이터, 가짜 API 응답, 로컬 시험 주문을 사용했다.

검증 대상 35개가 모두 통과했다. 마지막 안내 문구와 질문 포커스 수정 후 관련 질문 안내·다중 탭 테스트 9개도 다시 확인했다.

- 360·390·1280px에서 제작 코드 입력칸의 크기와 가로 넘침 확인, 화면 캡처 육안 확인.
- 수동 저장 후 홈 이동·새로고침·탭 닫기·같은 브라우저 재방문으로 작성본 복원.
- 저장 용량 오류 시 성공 안내를 표시하지 않고 기존 저장본과 화면 수정본 유지.
- 접수된 제작 중 탭 닫기, 응답 유실 후 새로고침: 새 POST 없이 기존 결과 복원.
- 화면 복귀 시 기존 상태만 재조회하고 새 제작 없음.
- 다른 제작코드로 기존 주문의 대기 기록 해제 불가.
- 중단된 주문의 서버 사유 표시와 대기 기록 복원.
- 제작 연결 확인 실패 후 같은 페이지에서 재확인 성공.
- 핵심·후속·요약·선택 질문 안내와 주인공 입력값 저장, 수정 화면 안내 유지.
- 동시 질문 저장·다른 탭 삭제·파일 복원 충돌 보호.
- 실제 로컬 API를 통한 완성본 글·그림 18장 복원과 PDF 다운로드 5회, 고객 수정본 유지, 잘못된 코드 거절.
- 합성 관리자 계정의 주문별 자산 접근 제어와 PDF 다운로드.

검증 중 같은 저장본을 두 탭이 동시에 복원하면 정상화된 내용이 같아도 충돌로 판단하는 문제를 발견해 수정했다. 저장값이 정확히 같은 경우에는 쓰기 없이 일치 상태로 처리하고, 내용이 다르거나 삭제된 경우에는 기존 충돌 보호를 유지한다. 결정적인 동시 복원 회귀 시험을 추가했다.

타입 검사·프로덕션 빌드·질문 엔진·저장/파일 복원·클라우드 모의 시험도 통과했다. 클라우드 모의 시험에서는 접수된 고객 연결을 끊은 뒤 글과 그림 18장 완성과 중복 생성 방지를 확인했다.

재실행:

```sh
npm run build
# 시험용 서버와 관리자 검증은 실제 운영 비밀번호 대신 합성 시험 비밀번호를 사용한다.
npm start -- --hostname 127.0.0.1 --port 3110
# TEST_ADMIN_PASSWORD는 시험 서버의 OFFICE_ADMIN_PASSWORD와 같은 합성 값으로 설정한다.
TEST_BASE_URL=http://127.0.0.1:3110 PLAYWRIGHT_EXECUTABLE_PATH=/usr/bin/chromium npm run test:checkout:browser
```

관리자 시험 비밀번호를 설정하지 않으면 관리자 전용 2개는 건너뛴다. 기본 Playwright 설정은 기존 Edge를 유지하며, 위 실행만 설치된 Chromium을 선택한다.

## 운영 확인과 한계

기존 공개 사이트의 /api/storybook/availability를 읽기 전용으로 확인해 HTTP 200과 ready:true를 받았다. 이는 현재 배포본의 연결 상태이며 이번 수정본의 배포 검증이 아니다. Netlify 배포·기본 브랜치 병합·실제 입금·유료 제작은 하지 않았다.

실제 휴대폰 앱 강제 종료, 운영 서버 장애, 실제 Netlify Background Function의 유료 제작은 검증하지 않았다. 모바일 화면 크기는 데스크톱 Chromium의 뷰포트 시험이다. OS 강제 종료 직전 아직 저장되지 않은 입력의 완전한 보존까지 보장하지 않는다.

전체 기존 테스트 파일에 대한 npm run typecheck:browser는 기존 파일의 암시적 any 및 Page.documentElement 타입 오류로 실패한다. 이번에 추가·수정한 checkout-safety, question-guidance, question-concurrency와 전용 설정의 엄격한 타입 검사는 별도로 통과했다. 전체 브라우저 회귀 묶음이 모두 정상이라고 확대해서 보고하지 않는다.
