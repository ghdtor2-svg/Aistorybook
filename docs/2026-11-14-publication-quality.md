# 질문 예시·출고 검수·PDF 출력 보완

## 반영한 내용

- 핵심/후속 질문의 실제 답변 대상 7가지, 요약 항목, 선택 질문 9가지, 허용할 각색 안내 아래에 ‘예)’로 시작하는 문장 예시를 추가했다. 예시는 화면 안내이며 답변에 자동 입력하거나 제작 요청에 복사하지 않는다.
- 새 글 생성 후 별도의 편집 검수 1회를 거친다. 목표·행동·결과의 인과, 장소·시간·소품 연속성, 주인공과 관계, 원래 사연과 금지 요소, 한국어 문장, 자연스러운 결말 6항목을 확인하고 고친 완성본을 받는다. 한 항목이라도 통과하지 못하거나 검수 형식이 없으면 초안을 완성본으로 저장하지 않는다. 손상된 Unicode도 거절한다. 불확실한 유료 응답을 자동 재시도하지 않는다.
- 검수는 글 생성 API 호출을 최대 1회 추가한다. 짧은 초안 보완 1회가 필요한 경우 총 최대 3회(초안·분량 보완·검수)다. 각 호출 전 서버 진행 시각과 검수 단계를 갱신한다. 실제 AI 검수 품질과 운영 원가는 이 모의 시험만으로 보장하지 않는다.
- 현재 Gaegu 700의 실제 cmap을 조사한 결과 현대 한글 11,172자 중 2,350자만 들어 있고 ‘렜’은 없다. 이 경우 글자 하나만 다른 글꼴로 나오는 문제가 있었다. 해당 글자를 포함하면 책 본문 전체를 한글 완성형 11,172자를 지원하는 Noto Sans CJK KR 기반 글꼴로 통일한다. 일반 글자는 기존 Gaegu를 유지한다.
- 글꼴은 외부 CDN 대신 서비스의 public/fonts에서 제공한다. 400/700 두 파일에 한글 완성형이 모두 있는지 확인했다. PDF 글꼴 로딩 실패 시 다른 글꼴로 조용히 출력하지 않고 다운로드를 차단하고 재시도를 안내한다. 글꼴 출처와 OFL은 public/fonts/OFL-Noto.txt에 보관한다.
- PDF 쪽 번호는 그림 색에 묻히지 않도록 종이색 상자·테두리·진한 숫자로 고정한다. 본문 번호 1~32를 모두 그린다.
- 이전 마지막 본문 쪽을 두 면에 나누어 PDF 17쪽 오른쪽까지 본문으로 채운다. 기존 첫 30면의 배치와 삽화 연결은 유지하고 마지막 그림도 재사용한다. 기존의 좁은 마지막 그림은 전체가 보이도록 담는다. 새 삽화나 AI 이미지 호출은 추가하지 않는다.
- 마침은 별도의 마지막 PDF 18쪽이다. 화면도 별도 ‘끝’ 카드를 표시한다. 구성은 표지 1 + 본문 펼침면 16 + 마침 1 = PDF 18쪽, 본문 낱면 32쪽 + 표지·마침 = 낱면 기준 총 34쪽이다. 그림은 기존과 같이 18장, 가격은 그대로다. 품질 상수와 고객 구성 안내를 이에 맞췄다(기존 고정 샘플 작품은 변경하지 않음).

## 검증

- 타입 검사와 프로덕션 빌드 통과.
- 한글 안전 글꼴 선택·손상된 문자 거절·검수 통과 조건·본문 전체 보존·32면/16펼침면/17본문그림 구성 테스트 통과.
- PDF 구조(18쪽), JPEG 스트림, xref, 한글 제목 검사 통과.
- 6개 합성 동화 × 그림 18장의 장면 프롬프트 회귀 검사 통과.
- 클라우드 모의 시험: 초안과 검수 각 1회, 검수 실패 시 완성본 미저장, 중복 실행 방지, 화면 이탈 후 복구, 그림 18장 유지 확인. 실제 AI 호출은 없음.
- Chromium 브라우저 시험 36개 통과. 다섯 번의 실제 PDF 파일 생성, 본문 번호 1~32와 별도 ‘끝’ 1회 그리기, ‘설렜어요’에 안전 글꼴 적용, 글꼴 요청 실패 시 다운로드 차단, 질문 예시 표시와 기존 저장·복구 회귀를 확인했다.
- 합성 동화 PDF의 2·17·18쪽을 PDF 렌더러로 열어 육안 확인했다. 17쪽 양쪽에 본문과 번호 31/32가 나오고 18쪽에는 ‘끝’과 제목이 나온다.

## 기존 파일과 범위

첨부된 고객 PDF는 쪽마다 글과 그림이 이미 합쳐진 JPEG를 담은 파일이며 텍스트 계층이 없다. 이 파일의 원본 문장·그림을 임의로 덧칠하거나 새 내용으로 바꾸지 않았다. 해당 동화의 수정 PDF는 원래 책장/서버 보관본을 수정된 출력 코드로 다시 내보내야 한다. 책장 백업 JSON이 있으면 동일 원문으로 재출력할 수 있다. 고객 PDF와 사연·이름은 저장소에 올리지 않는다.

기존 완성본의 이야기 내용은 자동 AI 재작성하지 않는다. 내용 검수는 새 생성에 적용된다. 실제 생성 결과의 개연성이 항상 완벽하다고 주장하지 않으며 유료 실생성 검증은 별도다. Netlify 배포와 기본 브랜치 병합은 하지 않았다.
