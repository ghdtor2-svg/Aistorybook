# AI OFFICE — 2단계

개인화 AI 동화 플랫폼을 개발·운영하기 위한 가상 사무실입니다.
직원은 AI 개발자, AI 기획·리서치, AI 마케팅, AI 품질관리·디자인의 네 명입니다.
별도의 총괄 직원 없이 시스템 규칙으로 주 담당과 협업 직원을 자동 배정합니다.

## 실행
이 파일이 있는 폴더에서 실행하세요. Windows PowerShell에서는 npm.cmd를 사용합니다.

```powershell
npm.cmd install --cache .npm-cache
npm.cmd run dev -- --hostname 127.0.0.1
```

접속: http://127.0.0.1:3000
역할별 예시 버튼 → 배정 미리보기 → 업무 시작 → 직원별 결과물 확인.
입력 변경 시 이전 배정과 보고서를 초기화하여 현재 업무와 혼동되지 않게 합니다.

## 배정과 상태
역할별 키워드 일치 개수가 가장 많은 직원을 주 담당으로 정합니다.
동점은 직원 목록 순서로 정하며 일치 항목이 없으면 기획·리서치가 담당합니다.
다른 역할에도 일치 항목이 있으면 협업에 포함하고, 개발·마케팅에는 품질 검토를 추가합니다.
주 담당부터 순차 보고하며 협업자는 앞선 결과를 인계받습니다. 품질관리 협업은 마지막입니다.
직원 카드는 대기 / 배정 예정 / 결과 대기 / 완료 / 실패 상태를 표시합니다.
현재는 전체 결과를 한 응답으로 받으므로 개인별 실시간 실행 단계는 표시하지 않습니다.

## 데모 전용
API 키가 없어도 실행됩니다. 키와 환경 설정에 관계없이 실제 OpenAI 연결은 비활성화됩니다.
POST /api/run의 auto 및 demo 모드는 데모로 실행하고 live 요청은 503으로 차단합니다.
기존 OpenAI 연동 코드는 src/lib/openai-workflow.ts에 보존했으나 라우트에서 사용하지 않습니다.
데모는 규칙 기반 업무 초안입니다. 실제 코드 수정, 외부 조사, 사실 검증, 게시를 수행하지 않습니다.
고객용 하이브리드 질문형 동화 생성은 다음 단계입니다. 현재 질문 제안은 내부 기획 초안입니다.

## 검사
```powershell
npm.cmd run typecheck
npm.cmd run build
# 빌드 완료 후 개발 서버를 시작하거나 재시작한 다음 실행
npm.cmd run test:smoke
```
개발 서버 실행과 빌드를 동시에 수행하면 .next 캐시 충돌이 발생할 수 있습니다.
분석 및 변경 내역: STAGE2.md. 1단계 기록: ANALYSIS.md.
DB 저장, 인증, 작업 큐, 스트리밍, 외부 검색은 아직 구현하지 않았습니다.

## 3단계 고객용 질문 페이지
`/storybook`에서 개인 추억을 핵심 질문·규칙 기반 후속 질문으로 수집합니다.
API 없이 동작하며 답변과 초안을 브라우저 localStorage에 저장합니다.
수정·건너뛰기·요약 편집·최종 확인·저장 삭제를 제공합니다. 동화 생성은 4단계 예정입니다.
질문 수 제한, 데이터 구조, 보안 범위, 테스트 결과는 STAGE3.md를 참고하세요.
추가 테스트: `npm.cmd run test:engine`, 서버 실행 후 `npm.cmd run test:browser`.

## 4단계 공동 프로젝트 작업실
`/office`에서 프로젝트별 업무 등록, 직원 추천/수동 지정, 단계별 협업 데모, 직원별 결과 및 대표 승인·반려를 관리합니다.
반려 후 재작업은 새 회차로 기록하고 이전 이력을 보존합니다. 업무는 별도 브라우저 저장 키를 사용하며 /storybook 답변을 수정하지 않습니다.
기존 홈 대시보드와 /storybook은 그대로 유지합니다. 실제 AI·코드 수정·외부 실행은 하지 않습니다.
백업 위치, 변경 파일, 검증 결과, 다음 단계 범위는 STAGE4.md를 참고하세요.
추가 테스트: `npm.cmd run test:office`.

## 5단계 서버 전용 실제 AI 실행기
/office에 실제 AI 모드, 로컬 관리자 인증, 토큰/호출 상한, 월간 예산과 프로젝트별 비용 기록을 추가했습니다.
기본은 데모이며 최초 유료 호출 승인 전에는 실제 실행 플래그를 켜지 않습니다. 프로덕션 유료 실행은 금지됩니다.
서버 설정·인증·보안 한계·검증 결과·최초 유료 검증안은 STAGE5.md를 참고하세요.
추가 무과금 테스트: `npm.cmd run test:live` (공식 SDK mock transport, 실제 API 호출 없음).

/office에서 사계절 캐릭터와 3D 공간을 기존 업무 상태에 연결했습니다. GPT 구독 모드는 기획·개발·마케팅·품질관리 모두 같은 ChatGPT 연결을 사용합니다. 데모 기본 모드와 기존 업무/동화 저장소는 유지합니다. 실제 기획 텍스트 1회, 네 역할 모의 실행·타입·빌드·브라우저 회귀 8개를 검증했습니다. Gemini 연결은 진행하지 않습니다. 상세 변경·보존·검증·한계는 STAGE6_2.md를 참고하세요.


## 동화 책 꾸미기 — 겉 표지와 내지 (2026-11-05)
만든 동화를 글만 흐르는 화면이 아니라 **한 권의 책**으로 보여 줍니다.
겉 표지는 전면 그림 + 제목판 + 책등 그림자, 내지는 장 머리 밴드 삽화 + 장 번호 + 짧은 괘선 +
양끝맞춤 본문 + 장 끝 장식입니다. 화면에서 읽을 때와 `읽을 수 있는 동화 파일`로 내려받을 때가
같은 조판을 씁니다(`src/lib/storybook/book-design.ts` 한 곳).

화풍과 규격은 인쇄용 샘플 책(`신규플랫폼_가치기반_동화/책`)에서 가져왔습니다 — 수채 색면과
연필선 필터, 본문 들여쓰기 1em, 장 표제 자간, 괘선 색까지 같습니다. 그래서 화면에서 읽은 책과
실제로 찍은 책이 한 권으로 보입니다.

그림은 **전부 인라인 SVG** 입니다. 외부 요청이 없어 내려받은 파일이 인터넷 없이도 열리고,
확대해도 깨지지 않아 인쇄에 그대로 씁니다. 표지 그림은 책 아이디로 고르므로 같은 책은
언제 열어도 같은 표지이고, 책마다 다른 표지가 나옵니다.
그림을 더 넣으려면 `src/lib/storybook/book-art.ts` 의 목록에 SVG 를 한 장 추가하면 됩니다.
화면·내려받기·인쇄가 같은 목록을 쓰므로 세 곳이 함께 바뀝니다.

인쇄는 '배경 그래픽'이 꺼진 채로 나가는 것이 보통이라, 인쇄에서는 제목을 그림 위에 얹지 않고
그림 아래로 내립니다. 제목이 그림에 묻히지 않습니다.

추가 테스트: `npm.cmd run test:book` (표지 고정·그림 목록·내려받은 파일 조판·임시 차단).
